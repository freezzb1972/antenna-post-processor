# /gui-design — GUI 设计审核

收到 GUI 相关需求时，**先设计讨论，确认后再写代码**。禁止直接动手改。

## 触发条件

用户消息含以下任一关键词时自动触发：
界面、窗体、按钮、布局、GUI、widget、dialog、页面、设置、弹窗、对话框、
输出设置、图表配置、参数页、控件、样式、字体、颜色、位置、大小

## 工作流

### Step 1: 读取现状

```bash
# 读取相关 UI 文件，了解当前布局和控件
```

### Step 2: 提出方案（2-3 个）

每个方案包含：
- **位置**：控件放哪里
- **控件类型**：ComboBox / Checkbox / Button / SpinBox...
- **与其他控件的关系**：是否替换、合并、移动
- **影响范围**：涉及哪些文件和类

### Step 3: 架构审核（可选）

如果改动涉及多个文件或类，调用 `architect` agent 审核：
```
Agent(architect, "审核 GUI 方案 X 的架构合理性")
```

### Step 4: 用户确认

用 AskUserQuestion 列出方案让用户选择，确认后进入实现。

### Step 5: 实现

按确认的方案修改代码，完成后运行 `gui-check` 验证。

## 反模式

- ❌ 用户提一句布局建议就立刻开始改代码
- ❌ 不提替代方案，只实现用户字面描述
- ❌ 不改动涉及多个类时不审查依赖关系
